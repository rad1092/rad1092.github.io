## 하는 일

HTTP 요청을 AI 클라이언트가 쓰려면 URL만으로는 부족합니다. 실제로 동작하는
호출, 모델이 이해하는 입력 설명, 토큰을 안전하게 둘 곳이 필요합니다. FirstCall은
이미 가진 요청을 읽고, 실제 값으로 보내 보고, 설명을 붙이고, 내보내는 네 단계로
도구를 만듭니다.

curl 명령, OpenAPI 명세, 브라우저 HAR 파일, Postman·Bruno 컬렉션, `.http` 파일,
Hurl을 읽습니다. 내보낸 결과는 FirstCall에 들어 있는 명령줄 런타임이 MCP 서버로
실행하는 폴더라서, 빌드할 코드도 npm이나 PyPI에서 설치할 것도 없습니다.

## 만든 방식

- Rust 코드 하나로 데스크톱 앱(egui)과, 내보낸 도구를 stdio로 실행하는 런타임
  `firstcall-cli`를 함께 빌드합니다.
- 내보낼 때 따로 허용하지 않으면 도구는 GET과 HEAD만 씁니다. 호출은 선언한
  주소로만 가고 리다이렉트는 거부합니다.
- 응답은 비밀값을 가린 구조화된 JSON으로 돌려줍니다. 크기 제한을 넘는 응답은
  잘라서 주지 않고 거부합니다.
- 토큰은 API별로 OS 키체인에 저장합니다. 서버 하나가 도구 여러 개를 실행해도 한
  API의 토큰을 다른 API에 넘기지 않습니다.
- 요청 기록과 검증한 요청은 로컬 SQLite에만 저장합니다. 백엔드가 없습니다.

## 내린 결정

- **성공한 요청에서만 내보내기.** 도구는 실제로 보내서 응답을 받은 요청에서
  시작하고, 패키지에 그 검증 기록이 남습니다. AI 클라이언트는 동작이 확인된
  호출을 받습니다.
- **생성 코드 없음.** 초기 버전은 빌드해야 하는 TypeScript 프로젝트를
  내보냈습니다. 지금은 런타임이 앱에 들어 있어서 내보낸 그대로 실행됩니다.
- **기본은 읽기 전용.** 도구를 부르는 쪽은 사람이 아니라 모델이라서, 쓰기
  메서드는 내보낼 때 명시적으로 고르게 했습니다.
